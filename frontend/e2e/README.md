# AverQel browser E2E harness

The browser suite is an isolated contract harness. Playwright starts a fresh
loopback Next server for each command, the server never reuses a developer
process, and API calls are fulfilled by the test fixtures or sent to a closed
loopback sink. It does not use a production, staging, or developer database.

## Commands

Run these from the repository root:

```bash
pnpm --dir frontend e2e
pnpm --dir frontend e2e:smoke
pnpm --dir frontend e2e:deepspace
pnpm --dir frontend e2e:documents
```

The smoke matrix covers the public homepage, onboarding/profile/theme, and
authenticated route reachability. DeepSpace covers durable runtime controls,
queue resume/retry/edit/regeneration, adaptive budget metrics, and responsive
Library reachability. `deepspace-visual-workflow.spec.ts` covers generated chat
visuals, rendered note reopen, chart edits syncing to the note and saved artifact,
artifact edits syncing back to chat and note, reload, and a second isolated
browser context using the same private test account. It also checks that a
delayed note autosave cannot roll back a newer artifact revision. It checks SVG/PNG/PDF
downloads for charts, cards, galleries, graph diagrams, and Mermaid, plus
Mermaid source and an owned gallery photo embedded in exports. Its APIs are
intercepted test fixtures; it is a browser workflow contract, not a live backend
or physical second-device run. Backend isolated integration tests separately
cover durable message versions and revision conflicts.

`deepspace-library-heavy-files.spec.ts` also covers an image becoming sendable
while background OCR remains pending. Its API is mocked; backend unit tests
cover the worker lock/cancellation race and deferred extraction metadata.

To feed a chart generated by a local model into the browser workflow, place its
DeepSpace Markdown response in a temporary file and set
`DEEPSPACE_E2E_VISUAL_MARKDOWN_FILE=/tmp/response.md` before running the visual
spec. Without that variable the test uses a deterministic chart fixture. The
test validates the chart fence schema before opening the browser.
Documents covers quarantine review, organization
webhooks, secure share links, grounded citations, and PDF preview controls.

## Failure evidence

Failed tests keep a screenshot, video, Playwright trace, and browser
diagnostics attachment under `frontend/test-results`. An HTML report is
written to `frontend/playwright-report`; open it with:

```bash
pnpm --dir frontend e2e:report
```

The shared fixture records page errors, console errors, and failed requests as
JSON evidence without turning intentionally mocked provider failures into
false test failures.

## Disposable external validation

External browser runs are disabled unless both variables are supplied:

```bash
DEEPSPACE_E2E_ALLOW_EXTERNAL=1 \
DEEPSPACE_E2E_BASE_URL=https://disposable-staging.example \
DEEPSPACE_E2E_STORAGE_STATE=/path/to/short-lived-state.json \
pnpm --dir frontend e2e
```

Use only a disposable environment and short-lived test credentials. The
Playwright configuration refuses an external URL or credential without the
explicit opt-in.
